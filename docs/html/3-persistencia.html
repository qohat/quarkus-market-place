Módulo 3 · persistencia

El esquema es el contrato

Flyway manda e Hibernate obedece. Y el bug más caro de esta capa no rompe nada: solo hace que la aplicación vaya lenta cuando ya hay datos de verdad.

Quién manda sobre el esquema

drop-and-create

Hibernate deduce las tablas de tus entidades. Cómodo para empezar y una trampa a medio plazo: el esquema real acaba siendo lo que Hibernate improvise, sin control de versiones.

validate + Flyway

Las migraciones crean el esquema; Hibernate solo comprueba que las entidades encajan al arrancar. Si añades un campo y olvidas la migración, no arranca.

Y esa red de seguridad se cobró enseguida

Schema validation: wrong column type in price_currency: found [bpchar], expecting [char(3)]

CHAR(3) en PostgreSQL es bpchar: rellena con espacios hasta la longitud fijada. Casi nunca es lo que quieres.

VARCHAR(3) en la migración. Lo detectó validate, que fue justo su razón de ser.

Paginación: el desempate no es estético

Con ORDER BY title a secas, dos publicaciones tituladas igual quedan en un orden que PostgreSQL no garantiza y puede cambiar entre consultas.

Un elemento que estaba en la página 1 reaparece en la 2, y otro desaparece sin que nadie haya tocado nada. Es un bug clásico, difícil de reproducir y que solo se manifiesta con datos reales. Toda consulta paginada necesita un orden total.

El N+1, y por qué ningún test funcional lo detecta

Porque el resultado es correcto. El N+1 no es un bug de comportamiento: es un bug de coste.

No hay excepción ni log

Son consultas legítimas y rápidas cada una por separado.

Invisible con pocos datos

Con 20 filas, 21 consultas tardan milisegundos. El problema aparece con datos de verdad.

Depende del contexto, no del código

El mismo bucle cuesta 2 o 40 consultas según lo que la sesión hubiera cargado antes.

La defensa: presupuesto de consultas

Un test que no asegura qué devuelve el código, sino cuánto cuesta. Con las estadísticas de Hibernate, un N+1 pasa de problema invisible a build rojo. 

private long consultasDe(Runnable accion) {
    var stats = sessionFactory.getStatistics();
    stats.clear();
    accion.run();
    return stats.getPrepareStatementCount();
}

// La aserción ROBUSTA no es "exactamente 2 consultas" sino:
assertEquals(consultasDe(cargar20), consultasDe(cargar100),
        "el número de consultas no debe crecer con el volumen");
El N+1 que no ocurrió — el hallazgo más raro del módulo

El primer test escrito para demostrar un N+1 falló esperando más de 20 consultas y obtuvo 2. La caché de primer nivel de Hibernate se lo había tragado: los objetos ya estaban en la sesión, así que el bucle no volvió a la base de datos.

El mismo bucle cuesta 2 o 40 consultas según lo que la sesión cargara antes. Por eso el N+1 es tan escurridizo: un cambio inocuo aguas arriba lo enciende sin que nadie toque el bucle.

Bloqueo optimista: el lost update

Dos peticiones leen la misma fila, ambas deciden, ambas escriben. La segunda pisa a la primera sin que nadie se entere.

Hibernate añade AND version = ? al UPDATE. Si afecta a 0 filas, alguien se adelantó: OptimisticLockException → 409 Conflict, no un 500. El cliente puede releer y reintentar sabiendo qué pasó.

En el módulo 6 esto se pone a prueba de verdad, y se descubre que el bloqueo optimista pierde ventas bajo contención aunque haya stock de sobra.

Otras decisiones del módulo

DecisiónPor qué
EnumType.STRING, nunca ORDINALReordenar el enum cambiaría el significado de todas las filas ya escritas.
@Transactional en el caso de usoLa transacción delimita una unidad de trabajo del negocio. En el repositorio, una operación abriría tres transacciones distintas.
Entidades separadas del dominioJPA exige constructor vacío y mutabilidad; los records del dominio son inmutables.
SINGLE_TABLE con discriminadorUna tabla para productos y servicios, con CHECK condicionales por tipo.

Y un choque de Java que enseña más de lo que parece

PanacheListingRepository is not abstract and does not override abstract method count()

Java no elige entre un método abstract de una interfaz y un default de otra sin relación entre ellas. Y el arreglo evidente —llamar a PanacheRepositoryBase.super.count()— falló en runtime: «this method is normally automatically overridden in subclasses», porque declararlo te saca de la generación de bytecode de Quarkus.
