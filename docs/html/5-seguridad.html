Módulo 5 · seguridad

El rol no es la propiedad

@RolesAllowed("seller") comprueba que eres un vendedor. No comprueba que seas el vendedor de esa publicación. Esa diferencia encabeza el OWASP API Top 10.

Las siglas, en orden histórico

Cada una nació para arreglar una carencia de la anterior.

OAuth 2.0

Autorización delegada: dar acceso a un tercero sin darle tu contraseña. Y no sabe quién eres — dice «el portador puede leer ventas», no «el portador es Qohat».

OIDC

Una capa fina encima que estandariza la identidad: ID token, endpoint /userinfo y descubrimiento automático. OIDC = OAuth 2.0 + identidad.

JWT

Solo un formato de token. Puedes hacer OAuth sin JWT y usar JWT sin OAuth. Tres bloques en base64 y una firma.

Un token real, campo por campo

Pulsa cada línea para ver qué hace.

Selecciona un claim.

El payload no está cifrado, solo codificado. Cualquiera con el token lee sus claims pegándolo en jwt.io. Un JWT no es un secreto: es un documento firmado, como un pasaporte.

Por qué JWT, de verdad

SESIÓN CLÁSICA                          JWT
cookie → id de sesión                   cabecera → token firmado
      ↓                                        ↓
consulta a un almacén compartido        verificación de la FIRMA
      ↓                                  con una clave pública ya descargada
una llamada de red por petición         cero llamadas de red

El servicio valida el token él solo. Con 30 microservicios, la alternativa —un almacén central de sesiones consultado en cada petición— es un cuello de botella y un punto único de fallo.

Y el precio: un JWT no se puede revocar

Es el reverso exacto de esa autonomía. Si echas a alguien, su token sigue siendo criptográficamente válido hasta que expire. Por eso los access tokens duran minutos —el nuestro, 10— y existen los refresh tokens, que sí son revocables porque canjearlos obliga a pasar por el emisor.

Alternativas más caras: lista de revocación por jti, o introspección en cada petición —que renuncia justamente a la ventaja que te llevó a JWT—.

El tercero se llama BOLA (Broken Object Level Authorization) y es el riesgo número 1 del OWASP API Security Top 10. No lo detecta ninguna herramienta automática: desde fuera, la petición es indistinguible de una legítima.

Se testea sin Quarkus

Los cuatro tests de propiedad corren en milisegundos, sin token y sin Keycloak.

private Listing transitionTo(ListingId id, ListingStatus nuevo, SellerId solicitante) {
    var listing = byId(id);                          // 404 si no existe
    if (!listing.sellerId().equals(solicitante)) {
        throw new NotTheOwnerException(id, solicitante);  // 403 si no es tuya
    }
    repository.save(listing.withStatus(nuevo));
    return ...;
}

Un solo punto: publish, pause y archive pasan todos por aquí. Añadir mañana destacar obliga a pasar por el mismo sitio, así que nace protegida. Una comprobación copiada tres veces es una que alguien olvidará la cuarta.

Y la identidad entra como parámetro explícito, no inyectada: la firma declara la dependencia, así que es imposible olvidarla. Al cambiarla, el compilador señaló exactamente los tres sitios que había que tocar.

403 o 404: cuándo mentir

403 Forbidden

«Existe, pero no es tuyo». Honesto con el dueño legítimo que se equivocó de cuenta.

404 Not Found

Miente a propósito. Impide enumerar qué identificadores existen.

Elegimos 403 porque las publicaciones ya son públicas vía GET /listings/{id}: fingir que no existe no oculta nada comprobable con otra petición. Para los pedidos, que sí son privados para leer, la elección correcta sería 404.

Los roles no estaban donde Quarkus los busca

Todo devuelve 403 aunque el token traiga los roles

Con el scope microprofile-jwt llegan en groups. Un Keycloak de producción suele ponerlos en realm_access.roles, y entonces la identidad llega sin ningún rol: autenticado y rechazado en todas partes.

quarkus.oidc.roles.role-claim-path=realm_access/roles

Un test intermitente de firma manipulada

Pasaba o fallaba según el token que tocara

Cambiar el último carácter de una firma base64 a veces no cambia los bits: los caracteres finales codifican relleno que se descarta al decodificar.
